## Service (`service.py`, rewritten)
- **Profile** stored as `{"id","name","age","kid","genres","duel_history","duel_done","reviews"}`; `kid = age < 13` server-side; genres are exact TMDB names; `duel_history` max 30 (`{picked,over,at}`, cards cut to id/title/year/genres); `reviews` max 30, newest last, a new review for the same film replaces the old one and moves to the end. Old profiles are filled with the new fields on read; nothing else is migrated (v3 wipes the table).
- **Member view** (`members` and `household` in `/api/state`, and `get_profiles`): `{name, age|null, kid, genres[], duel[] (last 10, "picked X (2014) over Y (2009)"), duel_done, reviews[{title,year,reaction,summary}] (last 10), new}`. No ids ever leave the service. `new` = no genres, or duel not done.
- **Genres -> duel**: `/api/genres` is TMDB's movie genres minus "TV Movie". `save_genres` resolves aliases (`sci-fi` -> Science Fiction), needs 1+ known name, and starts the duel only when the person never finished one and none is running; if the duel can't start the genres stay saved and the result carries `duel_error`. A new person (couch add) lands on screen `genres` with `genres_for`; everyone else re-saving genres stays where they are.
- **Duel**: the pool is the union of the person's genres' stored catalog cards, cert-filtered for the whole couch, shuffled; 5 pairs, a partner sharing no genre preferred; fewer than 10 films -> topped up from the other genres' kid-safe cards. Genre ids -> names comes from `tmdb.genres()` (cached in-process): no discover/search/movie/certification call at duel time, which the tests assert. No skip.
- **Catalog**: `seed_duel_catalog` builds per genre (TMDB discover, popularity.desc, `vote_count.gte=300`, 5 pages = 100 films, posters only, US certification per film) into `duelcat:<genre_id>` -> `{"genre","cards"(card+cert),"built_at"}`, only the missing genres, stops starting a new genre after 20 s, returns `{"built": [...], "remaining": [...]}`. A failed genre stays in `remaining` so the next call retries it; a built genre is never rebuilt.
- **Recommend** (`recommend(more)`): sets `picks_loading`, one `json_chat` call, 12 picks asked, TMDB search (year, then no year) -> `movie(id)` -> drop not found/no poster/duplicate id/cert not allowed -> first 10, `why` attached by film id (a film named twice keeps its first line), whys synthesized in parallel, cards + `shown_tonight` saved, screen `recommendations`. Under 4 cards: one retry, then `LLMError` (502).
- **Prompt**: static system message (12 films, `{"picks":[{title,year,why}]}`, one spoken spoiler-free line, never tells the model to use names); user message is one block per couch member (`Name (age)`, `Genres:`, `Duel picks:`, `Reviews: title (year): reaction - summary`), plus `<Name> is <age>. Only films rated US <cert> or lower that suit that age: no horror, strong violence, sexual content or strong language.` when `taste.max_certification` is not None (youngest minor decides), plus `Do not suggest these again: Title (Year), ...` when `more`.
- **Rating**: unchanged flow (one person at a time, five written reactions, skip, live words, finish). Spoken answers go through `voice_reaction`: the LLM turns the transcript into `{"reaction","summary"}`; the summary (15 words max, transcript as fallback) is saved with the review and shown as `RatingAnswer.quote`; `by` is `voice`/`hand`/`skip`. Button answers have `quote: ""`. Reviews are written once when the round ends, only for people who answered.
- **Removed**: `find_candidates`, `show_picks`, `mark_seen`/`mark_watched`/`_seen`, `watched`/`liked`/`disliked`, mood/`boost`, match score, `update_taste`/`_add_note`/`notes`, genre weights + `taste.nudge`/`vetoed`, `role`/`gender`/`named`, duel skip, `duel_candidates`, `start_auto_duel(pairs)`, shared duel pools (`warm_duel_pools`, `refresh_duel_pools`, `/api/duel/warm`), `push_speech`/`/api/speech`, agent leftovers. `taste.py` keeps aliases + `max_certification`, adds `youngest_minor`/`kid_rule`. `tmdb.py` loses `keyword_id` and the unused discover parameters.

## `llm.py` (new)
`OpenRouterLLM` on httpx like `voice_stt.py`: 20 s timeout, `Authorization: Bearer`, body `{model, messages, provider: {"only": ["cerebras/fp16"], "allow_fallbacks": false}, reasoning: {"effort"}, temperature, usage: {"include": true}}`, logs `10 in / 3 out / $0.000120`, returns `json_object(content)` (fenced block, else the first `{...}` that parses) or `None` when there is no object; HTTP/network/JSON errors raise `LLMError` -> 502. `POPCORN_REC_MODEL` (default `openai/gpt-oss-120b:nitro`) is in `config.py`; the key stays in `.env`. One manual smoke test against OpenRouter (key never printed): `chat openai/gpt-oss-120b:nitro: 109 in / 93 out / $0.000108`, JSON parsed, so the Cerebras pin and `reasoning` are accepted.

## Decisions (contract gaps)
- `duelcat:<genre_id>` has no household prefix (the contract spells the key that way; the catalog is a TMDB fact, built once for every household). Profiles and state stay `<household>:...`.
- `/api/speech` and `GET /api/rating` were agent-only (the TV never calls them) and are not in the contract table, so they are removed rather than kept.
- Changing the couch ends a running duel and empties `shown_tonight`; the reel itself stays if it was already showing. Deleting a person does not empty `shown_tonight`.
- The duel's kid filter is the person plus everyone on the couch (the contract's words), computed when the duel starts.
- `more` excludes `Title (Year)` strings, and duplicate ids are dropped inside one answer too (first line wins) so a repeated film can't eat a slot of the 10.
- `picks_loading` is cleared on every failure path, including a cancelled request, or the TV would spin forever.
- Rating summary: 15-word cap enforced in code, transcript used when the model returns no summary; empty transcript, non-JSON, or a reaction outside the five -> 400 "I didn't catch that, try again or use the buttons".
- `duel.shown` is still written because `types.ts` has it, though the TV never reads it.
- Seed order is TMDB's genre order, and the 20 s budget is checked before starting a genre, so one slow genre can't be cut in half.
